# Проверка зарегистрированного критерия до будущих матчей

Симуляция выполнена 05.11.2026. Будущие исходы не использованы.
Исходная регистрация и прогнозы сохранены без изменений. Дополнение публикуется
отдельно, с явным указанием новых операционных правил и уточнённой трактовки.

## Что проверено

Когорта 1000 матчей содержит **6 запланированных месяцев**, не 24.
Количество матчей по месяцам: ноябрь 144, декабрь 166, январь 241,
февраль 192, март 153, апрель 104. Переносы могут изменить фактическую структуру.
24 блока относились к историческому тесту из 3956 матчей.

Зарегистрировано условие U<0 для верхнего конца **двустороннего 95%** percentile CI.
При корректном equal-tail покрытии это номинальная левая ошибка **2,5%**, не 5%.
Односторонняя 95% верхняя граница соответствовала бы 5%. Корректно
калиброванное правило по доверительному интервалу является способом проверки гипотезы.

По каждому сценарию проведено 5000 независимых внешних симуляций; внутри каждой —
зарегистрированные 20000 месячных bootstrap-повторов, seed=0. Случайные блоковые
средние генерировались под нулевым эффектом, затем сдвигались на −0,007 для
оценки срабатывания при альтернативе. Исторический SD=0,196564.

Повторяющиеся наборы выбранных шести месяцев сжаты в уникальные векторы кратностей
с сохранением частот; weighted percentile воспроизводит буквальный bootstrap
из 20000 повторов. Эквивалентность проверена численно до 1e-14.

MC-интервалы отражают только погрешность 5000 симуляций внутри заданного сценария.
Это не интервалы для неизвестной реальной ошибки будущего эксперимента.
Нормальные сценарии задают разные внутримесячные ICC; в одном добавлена корреляция
соседних месяцев. Их параметры — допущения, а не установленные свойства будущих данных.
Исторические смеси — дополнительные синтетические сценарии с тяжёлыми хвостами,
также не гарантия поведения в будущем.

Метод недопокрывает при шести кластерах: даже при независимой нормальной модели
нулевой эффект ошибочно объявляется преимуществом примерно в 6,9% случаев,
а интервал покрывает нуль примерно в 86%, вместо 95%.
При заданной межмесячной зависимости ложное срабатывание около 14,9%.
Регистрация защищает от подгонки, но сама по себе не исправляет статистический метод.

## Как будет трактоваться пилот

Численное правило исходной регистрации остаётся неизменным и будет показано.
**Его срабатывание не будет названо валидированным статистическим подтверждением
с номинальной ошибкой 2,5% или 5%.** В свете симуляции эксперимент трактуется как
пилот с описательными результатами. Подтверждающий эксперимент с другим методом
потребовал бы отдельной проверенной и заранее зарегистрированной версии дизайна.
На будущих исходах метод не выбирается и замена критерия задним числом не делается.

Частота срабатывания при истинном эффекте −0,007 в заданных сценариях — примерно
13–32%, то есть отсутствие подтверждения встречается примерно в 68–87% случаев.
Это не «почти гарантированный» отрицательный итог и не доказательство отсутствия
эффекта. Повышенная частота ложных успехов также искусственно повышает эти показатели.
1000 матчей остаются пилотом без обещания достаточной мощности.

## Рыночные аномалии — правило для будущих данных

До оценки исходов добавлено объективное правило: полная тройка AvgCA/AvgCD/AvgCH,
каждое значение конечно и >1, сумма обратных коэффициентов от 1,00 до 1,20
включительно (допуск 1e-12 на границе). Выход за диапазон означает не установленную
ошибку источника, а непригодность для данного основного рыночного сравнения.
Сохраняются исходные значения и причина. Нет исправления догадкой, подмены
букмекера или коэффициентов открытия. Неоднозначные/конфликтующие строки также
непригодны. Один pinned-снимок данных и его хэш записываются до финального расчёта.

Знаменатель покрытия — исходные 1000 матчей; нужно минимум 950 пригодных троек.
Модель и рынок сравниваются на одной и той же подвыборке. При меньшем покрытии
рыночного вывода нет. Старое историческое сравнение 3956 матчей не пересчитывается
задним числом по новому правилу; аномальная историческая строка остаётся в основном
расчёте, её исключение уже показано как чувствительность.

## Переносы, отмены и срок

17.04.2027 — последняя исходная плановая дата, а не обещанный день анализа.
Дополнение фиксирует административную границу **30.06.2027 23:59:59 UTC**.
Перенесённая игра сохраняет ID и первый допустимый опубликованный прогноз;
доигранный матч до границы учитывается с фактической датой. Отменённый матч,
неподтверждённый результат, несыгранный технический исход или отсутствие допустимого
прогноза остаются в знаменателе 1000 и помечаются как пропуск, а не как нулевой счёт.
Новые игры на замену не добавляются. Если к границе нет всех 1000 исходов и
допустимых прогнозов, статус — «неполный эксперимент», без подтверждающего вывода.
Можно показать описательные метрики с точным числом доступных наблюдений.
Финальный анализ проводится один раз, без продления до значимости.

## Проверка публикации до начала

Для каждого batch сохраняются полный commit SHA, хэши файлов и серверное время
первой публичной публикации, которое должно предшествовать фактическому kickoff.
Git author/committer date сами по себе редактируемы и недостаточны.
Из публичной GitHub activity извлечён server pushedAt для исходной регистрации:
**05.11.2026 06:30:43 UTC**, commit 10ba208319d6b1f1d109331e5c99188fb680a222.
Pinned-файлы перечитываются и сверяются по хэшам. Поздние версии не заменяют
первый допустимый прогноз; неподтверждённое время публикации — пропуск покрытия.
Это публичная серверная запись, не независимый блокчейн-timestamp.
